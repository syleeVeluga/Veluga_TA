# OWPML / HWPX reference

`.hwpx` follows the national standard **KS X 6101 (OWPML)** — a ZIP + XML open
format. This is the structural reference the scripts rely on.

## Package layout

| Path | Role | Notes when writing |
|------|------|--------------------|
| `mimetype` | HWPX signature `application/hwp+zip` | **First ZIP entry + STORED (uncompressed).** OPC/EPUB/ODF rule. |
| `version.xml` | OWPML version / save environment | Keep template value. |
| `settings.xml` | Caret position, app settings | Usually kept as-is. |
| `Contents/content.hpf` | **OPF package**: `metadata` · `manifest` · `spine`. Every part is listed in `manifest`; read order = `spine`. | When adding a part, update `manifest` **and** `spine`. |
| `Contents/header.xml` | Shape tables (fonts, borderFills, char/para properties, styles), compatibility. Root `<hh:head>`. | Preserve style-ID reference integrity. |
| `Contents/section{N}.xml` | Section body. **Root local name `sec`** (section namespace). Body = `<hp:p> → <hp:run> → <hp:t>`. | When adding a section, sync `secCnt` (header) + manifest/spine. |
| `META-INF/container.xml` | OCF container → points at `content.hpf`. | Keep. |
| `META-INF/manifest.xml`, `container.rdf` | Part list / encryption info / RDF. | Keep. |
| `BinData/`, `Preview/`, `Scripts/` | Images·OLE / preview / scripts. | Images: add to `BinData/` **and** register in `content.hpf` manifest. |

Default fonts: **함초롬바탕(serif) / 함초롬돋움(sans)** — the HWPX default (not 맑은 고딕).

## Namespaces — extract at runtime, never hard-code prefixes

Part/version mixes (2011 / 2016 / 2021 / 2023) mean the same prefix can bind to
different URIs. Always read declarations from the document and address elements
by Clark notation `{uri}local`. `scripts/hwpx_common.py` does this:

```python
from hwpx_common import namespaces_of, register_all, local_name
ns = namespaces_of(section_bytes)   # {'hp': '.../2011/paragraph', 'hs': '.../section', ...}
register_all(ns)                     # so re-serialization keeps the prefixes
hp = ns["hp"]                        # resolve, don't assume
```

Common 2011 prefixes (defaults in `hwpx_common.NS`):

| Prefix | URI | Used in |
|--------|-----|---------|
| `hp` | `http://www.hancom.co.kr/hwpml/2011/paragraph` | paragraphs, runs, text, tables |
| `hs` | `http://www.hancom.co.kr/hwpml/2011/section` | section root `sec` |
| `hh` | `http://www.hancom.co.kr/hwpml/2011/head` | header.xml shape tables |
| `hc` | `http://www.hancom.co.kr/hwpml/2011/core` | core types (brushes, units) |
| `ha` | `http://www.hancom.co.kr/hwpml/2011/app` | settings.xml |
| `hpf` | `http://www.hancom.co.kr/schema/2011/hpf` | content.hpf package |
| `opf` | `http://www.idpf.org/2007/opf/` | manifest / spine |
| `hv` | `http://www.hancom.co.kr/hwpml/2011/version` | version.xml |
| `ocf` | `urn:oasis:names:tc:opendocument:xmlns:container` | container.xml |

> ⚠️ Do **not** look up elements as `getElementsByTagName('hs:section')`: the
> local name is `sec`, not `section`, and the prefix may differ — that lookup
> fails silently. Use `local_name()` / Clark notation instead.

## Body logical structure (KS X 6101 §10.2)

```
sec
└ hp:p          (paragraph, paraPrIDRef)
   └ hp:run     (charPrIDRef)
      ├ hp:t    ← text
      ├ hp:tbl  ← table (see reference/tables.md)
      ├ hp:pic  ← image (not generated by this skill)
      └ hp:ctrl ← controls (secPr lives here on the first paragraph)
```

The first paragraph of a section carries `<hp:secPr>` (page size, margins,
foot/endnote, page borders). When cloning paragraphs to add text, **strip
`secPr` from the clones** — only the first paragraph may hold it. `hydrate.py`
does this automatically.

## Units (HWPUNIT)

`1 inch = 7200 HWPUNIT`, `1 mm ≈ 283.46 HWPUNIT`. A4 page = `59528 × 84188`.
Character `height="1000"` = 10pt (height is pt × 100). The templates use a
content width of `42520` HWPUNIT (~150 mm) and `2835` (~10 mm) per table row.

## Updating non-body parts

- **Add a section:** `header.xml` `secCnt`++ and register `section{N}` in
  `content.hpf` manifest + spine.
- **Insert an image:** add the file under `BinData/`, register it in the
  `content.hpf` manifest with `media-type` + `isEmbeded`, and reference it from
  the body. (This skill does not author images automatically.)
